### 🧪 测试样例 1：基础逻辑与自我修复 (The Logic Test)

**目标**：验证 `Inspector` 的打回机制以及 `Developer` 的 **“手术刀修改” (replace_file_lines)** 能力。

**📝 Prompt (输入指令):**

> 写一个 Python 脚本 `fib_calculator.py`，计算斐波那契数列的第 100 位。
> **要求**：必须使用递归方式实现（这会导致性能问题/栈溢出，目的是诱导 Inspector 报错或超时），并编写一个 `test_fib.py` 来验证结果。

**👀 观察重点 (Dashboard):**

1. **Architect**: 设计文件结构。
2. **Developer**: 写出递归代码。
3. **Inspector**: 运行测试。由于递归计算第100位极慢或溢出，测试应该会 **超时 (Timeout)** 或 **报错 (RecursionError)**。
4. **关键点**：Inspector 应该报 **FAILED**。
5. **Developer (Return)**：收到报错后，应该将代码修改为 **“循环”或“记忆化递归”**。
6. **Token 验证**：观察 Developer 是否使用了 `replace_file_lines` 仅修改函数体，而不是重写整个文件。

### 🧪 测试样例 2：GUI 与 运行环境 (The GUI Test)

**目标**：验证 `Shell_Skills` 的防卡死机制（针对 Pygame 这种死循环程序）以及多文件协作。

**📝 Prompt (输入指令):**

> 写一个基于 Pygame 的“专注时钟” (Pomodoro Timer)。
> **功能**：显示 25:00 倒计时，有一个“开始/暂停”按钮，背景色随时间流逝从绿变红。
> **结构**：主逻辑在 `main.py`，UI绘制在 `ui.py`。

**👀 观察重点 (Dashboard):**

1. **Architect**: 定义 `main.py` 和 `ui.py`。
2. **Developer**: 即使是图形界面代码，也由 Developer 一人完成，检查 `main.py` 导入 `ui.py` 时变量名是否一致。
3. **Inspector**: 运行 `python main.py`。
* **关键点**：Pygame 窗口应该会弹出。
* 由于你的 `run_shell_command` 设置了 timeout，Inspector 不会卡死，而是几秒后报告 `[TIMEOUT]` 并视为 **PASSED** (因为没有报错堆栈)。


4. **最终交付**：你应该能手动运行 `output/pomodoro_timer/main.py` 并看到一个可用的倒计时器。

### 🧪 测试样例 3：联网与数据处理 (The Data Test)

**目标**：验证 `Web_Skills` (联网搜索) 和第三方库安装能力。

**📝 Prompt (输入指令):**

> 帮我分析一下 Python `requests` 库和 `httpx` 库的区别。
> **步骤**：
> 1. 上网搜索两者的最新对比（2024-2025年）。
> 2. 写一个 Markdown 表格文件 `comparison.md` 总结优缺点。
> 3. 写一个 Python 脚本 `benchmark.py`，分别用这两个库请求 `https://www.google.com` 各 10 次，计算平均耗时并打印。
> 
> 

**👀 观察重点 (Dashboard):**

1. **Developer**:
* 会调用 `web_search` 查找资料。
* 会生成 `comparison.md`。
* 会生成 `benchmark.py`。


2. **Inspector**:
* 运行 `benchmark.py` 时，可能会报错 `ModuleNotFoundError: No module named 'httpx'` (如果你环境里没装)。
* **关键点**：观察 Inspector 是否会尝试 `pip install httpx`，或者把错误踢回给 Developer，让 Developer 在 `requirements.txt` 里添加依赖。

### 💡 运行建议

为了保证测试顺利，建议在每次测试前：

1. **清理环境**：删除 `output/` 下的旧文件夹（防止文件名冲突干扰）。
2. **监控面板**：始终开着 `streamlit` 面板，盯着 **"Sequence Trace" (蛇形图)**，看是否出现了 `Developer -> Inspector -> Developer` 的回滚闭环。
